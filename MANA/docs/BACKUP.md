# پشتیبان‌گیری و بازیابی (دفترچه‌ها، پیام‌ها، عکس‌ها)

## چه چیزی پشتیبان گرفته می‌شود
دیتابیس کامل (حساب‌ها، برنامه‌ها، دفترچه‌ها، مرورهای شبانه، پیام‌ها، چت، تابلو آرزوها، مالی) و پوشه‌ی فایل‌ها/عکس‌ها (`storage`: عکس‌ها، تصویر آرزوها، پیوست‌ها).

## خودکار (استقرار با Docker)
سرویس `backup` در `deploy/docker-compose.yml` هر شب حدود ساعت ۳ (ساعت کانتینر، UTC) `server/scripts/backup.sh` را اجرا می‌کند و `mana-<تاریخ>.dump` و `files-<تاریخ>.tgz` را در volume `backups` می‌گذارد؛ نسخه‌های قدیمی‌تر از ۳۰ روز پاک می‌شوند (`KEEP_DAYS`).
```bash
docker compose logs backup            # دیدن گزارش
docker compose run --rm backup bash /backup.sh /backups   # گرفتن فوری یک نسخه
docker compose cp backup:/backups ./backups-copy          # بیرون آوردن نسخه‌ها
```
**روی همان سرور بماند کافی نیست:** هفته‌ای یک بار نسخه‌ها را به جای دیگری (هارد شخصی، فضای ابری رمزگذاری‌شده) ببرید.

## دستی (بدون Docker)
```bash
cd server && set -a && . ./.env && set +a
./scripts/backup.sh ~/mana-backups
```

## تست بازیابی (حتماً یک‌بار انجام دهید)
نسخه‌ای که هیچ‌وقت بازیابی‌اش را نیازموده‌اید قابل اعتماد نیست. این اسکریپت dump را در یک دیتابیس موقت برمی‌گرداند، شمار ردیف جدول‌های مهم را چاپ می‌کند و دیتابیس موقت را پاک می‌کند:
```bash
./scripts/restore-test.sh ~/mana-backups/mana-<تاریخ>.dump postgres://postgres:<رمز>@localhost:5432/postgres
```
(با Docker: داخل کانتینر `db` با کاربر `postgres` اجرا کنید.)

## بازیابی واقعی
```bash
pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL_OWNER" mana-<تاریخ>.dump
tar -C <STORAGE_DIR> -xzf files-<تاریخ>.tgz
```
سپس `npm run migrate` را اجرا کنید تا اگر نسخه‌ی برنامه جلوتر از dump است، مایگریشن‌های جدید اعمال شوند.

## وضعیت آزمون
در محیط ساخت: ساخت dump و خواندن فهرست آن با `pg_restore --list` تأیید شد (✔). اجرای کامل `restore-test.sh`، اجرای زمان‌بندی‌شده‌ی سرویس `backup` در Docker و حذف نسخه‌های قدیمی آزموده نشده است (◐) — در استقرار اول انجام دهید.

⚠️ پشتیبان‌ها داده‌ی خصوصی خانواده را دارند (از جمله دفترچه‌ی بچه‌ها): رمزگذاری و محدود نگهشان دارید.
